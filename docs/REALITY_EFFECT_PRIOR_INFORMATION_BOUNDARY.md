# Reality-Effect-Prior Information Boundary

**PR #22**: Foundation for General Algebra Architecture
**Status**: Governance documentation (no implementation)
**Created**: 2026-05-20

---

## Executive Summary

This document defines the **pre-Wadhʿ layers** of the project's algebraic architecture.

**Core principle**:
> **Wadhʿ is not the first algebraic contract.**

Before reaching Wadhʿ (linguistic convention linking Dal to Madlul), the system must account for:

1. **Source of Effect** - Where does the signal come from?
2. **Effect Reception** - What reaches the system?
3. **Prior Information** - What is already known?
4. **Effect-Prior Binding** - How are signals interpreted through prior knowledge?
5. **Candidate Madlul** - What are the possible meanings?
6. **Ordered Dal** - What is the structured form of the signifier?

Only after these layers can **Wadhʿ Contract** (Dal ↔ Madlul) be established.

## 1. Source of Effect

### Definition

A **Source of Effect** is the originating reality that produces signals reaching the system.

**Critical principle**:
> **"Reality" is not limited to sensory reality.**

### Source Types

The project recognizes **10 source types**:

#### 1.1 Sensory Reality
```text
Physical signals: sound waves, visual patterns, tactile input
Examples: spoken utterance, written text, gesture
```

#### 1.2 Mental Reality
```text
Internal cognitive states: thoughts, intentions, beliefs
Examples: internal reasoning, mental imagery, concepts
```

#### 1.3 Linguistic Reality
```text
Language as autonomous system: grammar rules, lexical items, patterns
Examples: morphological templates, syntactic constraints, phonological rules
```

#### 1.4 Social Reality
```text
Social constructs: institutions, roles, conventions, norms
Examples: speaker-hearer relationships, discourse context, social registers
```

#### 1.5 Technical Reality
```text
Domain-specific systems: algorithms, protocols, specifications
Examples: API definitions, technical standards, formal grammars
```

#### 1.6 Legal Reality (Shar'i Reality)
```text
Legal/religious systems: rulings, obligations, contracts
Examples: فقه terms, أحكام, عقود, Islamic legal concepts
```

#### 1.7 Mathematical Reality
```text
Mathematical structures: numbers, sets, functions, proofs
Examples: algebraic structures, logical propositions, formal systems
```

#### 1.8 Programmatic Reality
```text
Computational execution: code behavior, data structures, algorithms
Examples: function definitions, type systems, executable specifications
```

#### 1.9 Textual Source
```text
Pre-existing texts: classical sources, attestations, corpus data
Examples: Qur'anic text, hadith, classical grammar treatises, dictionaries
```

#### 1.10 Reported Source
```text
Transmitted information: reports, citations, references
Examples: "فلان قال", "في اللغة", "عند النحاة", scholarly transmission
```

## 2. Effect

### Definition

**Effect** is what actually reaches the system's boundary, regardless of source.

**Critical distinction**:
> **Effect is not Madlul yet.**

Effect is the **raw signal** before interpretation.

### Effect Types

#### 2.1 Sound
```text
Acoustic signal: phonemes, prosody, intonation
Input: spoken utterance
Not yet: meaning, intent, grammatical analysis
```

#### 2.2 Script
```text
Visual pattern: letters, diacritics, writing conventions
Input: written text
Not yet: pronunciation, meaning, parsing
```

#### 2.3 Image
```text
Visual representation: diagrams, pictorial content
Input: visual data
Not yet: symbolic interpretation
```

#### 2.4 Gesture
```text
Physical movement: pointing, nodding, hand signals
Input: embodied communication
Not yet: linguistic encoding
```

#### 2.5 Report
```text
Second-order signal: transmitted account
Input: "X said that..."
Not yet: verification, belief update
```

#### 2.6 Context
```text
Situational information: discourse context, world knowledge
Input: extra-linguistic cues
Not yet: contextual interpretation
```

#### 2.7 Text
```text
Structured linguistic input: sentences, paragraphs, documents
Input: ordered linguistic forms
Not yet: comprehension, analysis
```

#### 2.8 Definition
```text
Explicit specification: lexical definition, technical specification
Input: definitional content
Not yet: usage understanding, instantiation
```

#### 2.9 Event
```text
Observed occurrence: witnessed action, state change
Input: experiential data
Not yet: conceptual classification
```

#### 2.10 Signal
```text
Abstract information carrier: any transmittable data
Input: information-bearing pattern
Not yet: decoded content
```

## 3. Prior Information

### Definition

**Prior Information** is the "non-absolute zero" layer.

**Core principle**:
> **No Tasawwur (conceptualization) without Prior Information.**

The system is never a blank slate. It always brings:
- Previous experience
- Learned conventions
- Domain knowledge
- Classification systems
- Exemplars
- Rules

### Prior Information Components

#### 3.1 Lexicon
```text
Stored word forms and associations
Examples: معجم, قاموس, vocabulary lists
Not: real-time meaning construction (that requires binding)
```

#### 3.2 Attestation
```text
Recorded usage examples
Examples: شواهد from classical texts, corpus examples
Not: interpretation (that requires context binding)
```

#### 3.3 Classification
```text
Category systems: parts of speech, semantic fields, grammatical categories
Examples: اسم/فعل/حرف, مكان/زمان, متعدي/لازم
Not: assignment to current input (that requires analysis)
```

#### 3.4 Examples
```text
Stored instances: paradigmatic examples, prototypes
Examples: كَتَبَ as prototype of فَعَلَ, بيت as prototype of مكان noun
Not: pattern matching to input (that requires binding)
```

#### 3.5 Rules
```text
Explicit constraints: morphological rules, syntactic rules, phonological rules
Examples: الفاعل مرفوع, الفعل يتغير بالوزن, agreement rules
Not: application to current case (that requires operator governance)
```

#### 3.6 Domain Constraints
```text
Field-specific knowledge: technical terminology, specialized conventions
Examples: Islamic legal terms, mathematical vocabulary, technical jargon
Not: domain identification (that requires classification)
```

#### 3.7 Previous Experience
```text
Accumulated exposure: frequency data, collocations, common patterns
Examples: "كتاب is common", "ذهب يذهب follows pattern"
Not: current prediction (that requires probabilistic binding)
```

#### 3.8 Axioms
```text
Foundational principles: logical axioms, domain axioms, methodological principles
Examples: non-contradiction, linguistic compositionality, grammatical categories
Not: deduction (that requires inference licensing)
```

#### 3.9 Initial Facts
```text
Starting assumptions: pre-established knowledge, given information
Examples: "this is Arabic text", "speaker is competent", "context is formal"
Not: belief update (that requires evidence integration)
```

#### 3.10 Usage Conventions
```text
Pragmatic norms: speech act conventions, register rules, stylistic preferences
Examples: vocative يا, imperative افعل, polite forms
Not: pragmatic interpretation (that requires context binding)
```

## 4. Effect-Prior Binding

### Definition

**Effect-Prior Binding** is the **first cognitive contract** in the algebra.

**Formula**:
```text
Effect × PriorInformation → BindingCandidate
```

**Core principle**:
> **This contract is prior to linguistic Wadhʿ.**

### Binding Process

#### 4.1 Input
```text
Effect: raw signal (sound, script, context...)
PriorInformation: relevant stored knowledge
```

#### 4.2 Operation
```text
Match effect pattern to prior information patterns
Generate binding hypotheses
Rank candidates by:
  - similarity to exemplars
  - consistency with rules
  - frequency/familiarity
  - context fit
```

#### 4.3 Output
```text
BindingCandidate set, each carrying:
  - effect_source: which effect pattern matched
  - prior_source: which prior information was invoked
  - binding_strength: confidence/rank
  - residuals: unexplained aspects
  - counter_evidence: competing interpretations
```

### Critical Constraints

#### Constraint 1: No Binding Without Both Inputs
```text
❌ FORBIDDEN: Effect alone → interpretation
❌ FORBIDDEN: Prior information alone → prediction

✅ REQUIRED: Effect × Prior → BindingCandidate
```

#### Constraint 2: Binding is Hypothesis, Not Fact
```text
BindingCandidate is a CANDIDATE, not a determination.

It must carry:
  - rank (how confident)
  - evidence (why this binding)
  - counter_evidence (why not alternative bindings)
  - residuals (what doesn't fit)
  - trace (how was it derived)
```

#### Constraint 3: Multiple Bindings Expected
```text
Binding typically produces CandidateSet, not single answer.

Disambiguation requires further contracts (context, qarina, inference...).
```

## 5. Candidate Madlul

### Definition

**CandidateMadlul** is a licensed candidate produced by binding an effect to prior information.

**Formula**:
```text
CandidateMadlul = Bound(Effect, PriorInformation)
```

**Core principle**:
> **Madlul is not a primitive given.**
> **It is a constructed candidate requiring evidence.**

### Required Fields

Every `CandidateMadlul` must carry:

#### 5.1 Evidence
```text
effect_pattern: which effect pattern triggered this candidate
prior_match: which prior information supports it
binding_operation: how they were bound
```

#### 5.2 Counter-Evidence
```text
competing_candidates: alternative Madlul candidates
disambiguation_required: what additional information is needed
conflicts: which prior information contradicts this candidate
```

#### 5.3 Rank
```text
confidence: strength of binding [0.0, 1.0] or categorical rank
ranking_basis: why this rank (frequency, rule match, exemplar similarity...)
```

#### 5.4 Residuals
```text
unexplained_aspects: which parts of effect are not accounted for
missing_prior: what prior information would strengthen this candidate
gaps: what is assumed but not justified
```

#### 5.5 Trace
```text
derivation_path: step-by-step binding process
source_effect: original effect input
source_prior: original prior information
intermediate_steps: binding operations applied
```

#### 5.6 Missing Required Inputs
```text
required_context: what contextual information is needed
required_qarina: what disambiguating indicators are needed
required_licensing: what additional contracts must apply
```

### Prohibited Forms

#### ❌ Madlul Without Evidence
```text
# FORBIDDEN
madlul = "book"  # Raw string

# REQUIRED
madlul = CandidateMadlul(
    concept="BOOK",
    evidence=["lexicon match: كتاب → book", "context: library domain"],
    counter_evidence=["alternative: كَتَبَ → he wrote"],
    rank=0.8,
    residuals=["definiteness not determined"],
    trace=["effect: كتاب", "prior: lexicon entry", "binding: exact match"]
)
```

#### ❌ Madlul Without Prior Information
```text
# FORBIDDEN: Effect directly implies Madlul
effect = "كتاب"
madlul = interpret(effect)  # No prior information

# REQUIRED: Effect binds to Prior
effect = "كتاب"
prior = Lexicon.lookup("كتاب")
binding = bind(effect, prior)
madlul = CandidateMadlul(binding)
```

#### ❌ Single Madlul Without Alternatives
```text
# FORBIDDEN: Assume unique interpretation
madlul = determine_meaning(effect)  # Returns single answer

# REQUIRED: Generate candidate set
candidates = bind_effect_to_prior(effect, prior_info)
# Returns: [CandidateMadlul1, CandidateMadlul2, ...]
```

## 6. Ordered Dal

### Definition

**OrderedDal** is an ordered, bounded, internally composed linguistic signifier form.

**Formula**:
```text
RawDalEffect → OrderedBoundedDalCandidate
```

**Core principle**:
> **Dal is not raw sound or raw letters.**
> **It is an ordered, bounded, structured form.**

(See `docs/ORDERED_DAL_FORM_GOVERNANCE.md` for full specification.)

### Required Properties

Every `OrderedDal` must specify:

#### 6.1 Order
```text
sequence: [unit₀, unit₁, unit₂, ...]
indices: position of each unit
direction: left-to-right (Arabic) or right-to-left (analysis direction)
```

#### 6.2 Boundaries
```text
left_boundary: start boundary type (WORD_START, MORPHEME_START...)
right_boundary: end boundary type (WORD_END, MORPHEME_END...)
internal_boundaries: boundaries between internal units
```

#### 6.3 Units
```text
atomic_units: minimal units (letters, phonemes)
composed_units: higher-level units (syllables, morphemes)
unit_relations: prev/next, containment, adjacency
```

#### 6.4 Direction
```text
scan_direction: forward/backward/bidirectional
prev_unit: reference to preceding unit (or None)
next_unit: reference to following unit (or None)
```

#### 6.5 Previous/Next Relations
```text
previous: link to preceding OrderedDal (if part of larger structure)
next: link to following OrderedDal (if part of larger structure)
parent: containing structure (if nested)
```

#### 6.6 Fold Trace
```text
source_atoms: which atomic units were folded
fold_operations: how units were combined
reverse_trace: how to unfold back to atoms
```

#### 6.7 Residuals
```text
ambiguous_boundaries: uncertain boundary placements
competing_orders: alternative ordering hypotheses
unresolved_composition: unclear internal structure
```

#### 6.8 Rank
```text
order_confidence: how certain is this ordering
boundary_confidence: how certain are boundaries
composition_confidence: how certain is internal structure
```

### Prohibited Forms

#### ❌ Unordered Dal
```text
# FORBIDDEN: Bag of letters
dal = {"ك", "ت", "ب"}  # Unordered set

# REQUIRED: Ordered sequence
dal = OrderedDal(
    sequence=["ك", "ت", "ب"],
    indices=[0, 1, 2],
    boundaries=(WORD_START, WORD_END)
)
```

#### ❌ Boundary-less Dal
```text
# FORBIDDEN: No boundaries
dal = ["ك", "ت", "ب"]  # Just a list

# REQUIRED: Bounded sequence
dal = OrderedDal(
    sequence=["ك", "ت", "ب"],
    left_boundary=WORD_START,
    right_boundary=WORD_END,
    span=(0, 3)
)
```

#### ❌ Dal Without Trace
```text
# FORBIDDEN: Derived form without trace
dal_folded = fold(atoms)  # No trace

# REQUIRED: Trace preservation
dal_folded = OrderedDal(
    sequence=[syllable1, syllable2],
    fold_trace=FoldTrace(
        source_atoms=[atom0, atom1, atom2, atom3],
        operations=["CV-fold", "CVC-fold"],
        reversible=True
    )
)
```

## 7. Wadhʿ Contract

### Definition

**Wadhʿ Contract** is the algebraic linking of OrderedDal to CandidateMadlul with evidence.

**Formula**:
```text
WadhʿContractCandidate = OrderedDal × CandidateMadlul × WadhʿEvidence
```

**Core principle**:
> **Wadhʿ is not merely Dal ↔ Madlul.**
> **It is a three-way contract: Dal × Madlul × Evidence.**

### Required Components

#### 7.1 OrderedDal
```text
Structured signifier form (as defined in Section 6)
Must be: ordered, bounded, traced
```

#### 7.2 CandidateMadlul
```text
Hypothesized meaning (as defined in Section 5)
Must carry: evidence, rank, residuals, trace
```

#### 7.3 WadhʿEvidence
```text
Justification for linking Dal to Madlul

Evidence types:
  - lexicon attestation: dictionary entry
  - corpus frequency: observed usage
  - morphological derivation: pattern-based inference
  - contextual clue: qarina, context binding
  - explicit definition: stipulative wadhʿ
  - transmitted authority: classical source
```

### Wadhʿ Types

#### 7.3.1 Lexical Wadhʿ (وضع لغوي)
```text
Conventional linguistic assignment
Example: كتاب ↔ BOOK (lexicon entry)
Evidence: dictionary, attestation, usage
```

#### 7.3.2 Technical Wadhʿ (وضع اصطلاحي)
```text
Domain-specific assignment
Example: فاعل ↔ GRAMMATICAL_AGENT (syntactic term)
Evidence: technical definition, specialist usage
```

#### 7.3.3 Shar'i Wadhʿ (وضع شرعي)
```text
Religious-legal assignment
Example: صلاة ↔ RITUAL_PRAYER (not generic supplication)
Evidence: Islamic legal sources, fiqh definitions
```

#### 7.3.4 Stipulative Wadhʿ (وضع تعييني)
```text
Explicit definitional assignment
Example: "Let X denote Y"
Evidence: explicit stipulation, authorial intent
```

### Prohibited Wadhʿ Forms

#### ❌ Wadhʿ Without OrderedDal
```text
# FORBIDDEN: Raw string to meaning
wadhʿ = ("كتاب", BOOK)  # No ordered structure

# REQUIRED: OrderedDal to CandidateMadlul
wadhʿ = WadhʿContract(
    dal=OrderedDal("كتاب", boundaries=...),
    madlul=CandidateMadlul(BOOK, evidence=...),
    evidence=WadhʿEvidence(lexicon_attestation=...)
)
```

#### ❌ Wadhʿ Without CandidateMadlul
```text
# FORBIDDEN: Dal to raw meaning
wadhʿ = (OrderedDal("كتاب"), "book")  # Raw string meaning

# REQUIRED: Dal to CandidateMadlul with evidence
wadhʿ = WadhʿContract(
    dal=OrderedDal("كتاب", ...),
    madlul=CandidateMadlul(
        concept=BOOK,
        evidence=["lexicon", "corpus"],
        rank=0.9,
        ...
    ),
    evidence=WadhʿEvidence(...)
)
```

#### ❌ Wadhʿ Without Evidence
```text
# FORBIDDEN: Unjustified linking
wadhʿ = (dal, madlul)  # No evidence

# REQUIRED: Evidence-based contract
wadhʿ = WadhʿContract(
    dal=dal,
    madlul=madlul,
    evidence=WadhʿEvidence(
        type=LEXICAL,
        sources=["معجم", "شواهد"],
        confidence=0.85
    )
)
```

## Laws and Forbidden Transitions

### Core Laws

#### Law 1: No Effect Without Source
```text
Every Effect must declare its source or admit unknown source.

❌ FORBIDDEN: Effect appears without source specification
✅ REQUIRED: Effect(signal=..., source=SENSORY | TEXTUAL | ...)
```

#### Law 2: No Tasawwur Without Prior Information
```text
No conceptualization without prior knowledge.

❌ FORBIDDEN: Effect → Concept directly
✅ REQUIRED: Effect × Prior → CandidateMadlul
```

#### Law 3: No Candidate Madlul Without Effect-Prior Binding
```text
Madlul must be derived, not assumed.

❌ FORBIDDEN: Madlul as primitive
✅ REQUIRED: CandidateMadlul = Bound(Effect, Prior)
```

#### Law 4: No Ordered Dal Without Order, Boundary, and Trace
```text
Dal must be structured form, not raw signal.

❌ FORBIDDEN: Dal = raw letters
✅ REQUIRED: OrderedDal(sequence, boundaries, trace)
```

#### Law 5: No Wadhʿ Without OrderedDal and CandidateMadlul
```text
Wadhʿ is contract between structured form and evidenced meaning.

❌ FORBIDDEN: Wadhʿ(raw_string, raw_meaning)
✅ REQUIRED: WadhʿContract(OrderedDal, CandidateMadlul, Evidence)
```

### Forbidden Transitions

#### Forbidden 1: Effect → Madlul Without PriorInformation
```text
❌ Cannot jump from raw signal to meaning without prior knowledge
✅ Must bind effect to prior information first
```

#### Forbidden 2: RawForm → Dal Without Ordering and Boundaries
```text
❌ Cannot treat unstructured input as Dal
✅ Must construct OrderedDal with boundaries and trace
```

#### Forbidden 3: Dal → Madlul Without WadhʿContract
```text
❌ Cannot assume Dal directly means something
✅ Must establish Wadhʿ contract with evidence
```

#### Forbidden 4: Reality-Free Madlul
```text
❌ Cannot posit Madlul without source effect
✅ Madlul must trace back to effect-prior binding
```

#### Forbidden 5: Prior-Free Tasawwur
```text
❌ Cannot conceptualize without prior information
✅ Tasawwur requires prior knowledge base
```

#### Forbidden 6: Order-Free Dal
```text
❌ Cannot represent Dal as unordered bag of features
✅ Dal must be ordered sequence with boundaries
```

#### Forbidden 7: Evidence-Free Wadhʿ
```text
❌ Cannot assert Wadhʿ without justification
✅ Wadhʿ must carry evidence (lexicon, attestation, definition...)
```
